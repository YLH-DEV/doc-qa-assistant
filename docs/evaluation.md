## 二、为什么第 4、5 题最重要

在退费、价格、售后这类场景，**编一个答案的代价远大于说"不知道"**。

对比实验（同一份资料、同一个问题）：

| 提示词配置 | 问"支持花呗分期吗" | 结果 |
|---|---|---|
| 不加约束 | 顺着答"支持，可分 3-6 期" | ❌ 编造 |
| 加三条硬规则 | 「资料里没有相关信息」 | ✅ 拒答 |

所以第 ③ 条规则（资料里没有就直接说没有，不许推测）是这个项目里**最重要的一行提示词**。

## 三、踩坑复盘（真实调试记录）

### 坑 1：分块把标题和正文切开了 → 模型答"资料里没写价格"

**现象**：问"多少钱"时，模型回答"资料里没有统一价格"，但价格表明明在资料里。

**诊断**：打印命中的段落发现 —— 命中的是标题块 `## 四、价格`，而具体数字在**下一个块**里。
按空行切块时，标题和它下面的表格被切成了两块，模型只看到标题、看不到数字。

**修复**：分块时判断 —— 如果上一块是短标题（以 `#` 开头且长度 < 60 字符），
就把它和下一块合并。修完"多少钱"能正确答出「基础版 ¥299 / 标准版 ¥699」。

**教训**：**分块策略对召回质量的影响，比换模型大得多。**

### 坑 2：表格类内容按段落切会散

**现象**：价格表、退费档位表答不准。

**处理**：Excel 按"行"切块（一行一个块），而不是按段落。

### 坑 3：环境变量没生效，静默回退到本机模型

**现象**：配置了 key 但输出仍显示"本机 Ollama 兜底"。

**原因**：`.env` 文件没保存成 `.env`（记事本默认加了 `.txt`），或环境变量是旧终端设的。

**修复**：`.env` 必须用"另存为 → 所有文件"创建；改环境变量后要**新开终端**。
脚本里也加了显式输出"当前使用模型"，避免静默回退。

## 四、成本测算

按官方单价（deepseek-flash，空闲时段）：

| 项目 | 单价（每百万 token） |
|---|---|
| 输入 · 缓存未命中 | ¥1 |
| 输入 · 缓存命中 | ¥0.02 |
| 输出 | ¥4 |

**实测一次问答**：输入 342 token、输出 866 token

```text
输入缓存未命中：0.4M × ¥1    ≈ ¥0.0004
输入缓存命中：  16.3M × ¥0.02 ≈ ¥0.0003
输出：          0.28M × ¥4    ≈ ¥0.0011
合计 ≈ ¥0.0038 / 次
```

**规模换算**：

| 用量 | 月成本 |
|---|---|
| 1000 次/月 | ≈ ¥3.8 |
| 每天 500 次（15,000 次/月） | ≈ ¥57 |

**关键观察**：缓存命中率实测 **97.6%**，而命中价是未命中价的 **1/50**。
所以"省成本"的第一手段不是换模型，而是**保住缓存命中率**
（别频繁改 system prompt、别把上下文顺序打乱）。

## 五、这套验收标准可以直接拿去用

不管你用什么方案（自建 / SaaS / 外包），验收就问这 5 类问题：

```text
① 资料里有的 → 答对了吗？给出处了吗？
② 资料里没有的 → 它说"没有"了，还是编了？
③ 资料里写得含糊的 → 它是猜了，还是提示"规则未写明，建议人工确认"？
④ 资料更新后 → 同步了吗？旧答案还留着吗？
⑤ 一次问答多少钱？1000 次多少钱？
```
